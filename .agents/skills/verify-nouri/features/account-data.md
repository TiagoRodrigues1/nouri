# Data export

Log something first (a glass of water is enough) so the export has rows to check. Choose `Open user menu`. Clerk's panel lists `Manage account`, `Download my data`, and `Sign out`. Choose `Download my data` and wait for the browser's download event; the file is named `nouri-export-<date>.json`, using the server's UTC date. Save it with Playwright's `download.saveAs` into `$EVIDENCE`.

The file has `"format": "nouri-export/1"`, `exportedAt`, `account` with the account's `id` and `created_at`, and a `tables` object with one array per table that holds the person's rows (`food_entries`, `water_entries`, `mutation_receipts`, `progress_photos`, and the rest; a table with no rows is `[]`). The logged water appears in `water_entries`, and its retry receipt appears in `mutation_receipts`, next to the receipts of every other write. Deleted entries are exported too, with `deleted_at` set. `wearable_connections` rows never contain `refresh_token` or `access_token`; on the default run that table is empty, so export again while the [fixture-backed connection](wearables.md) is connected to see a row without them. Photo `image` values are base64.

Account deletion is not driven in the browser. It starts in Clerk and reaches Nouri as a signed `user.deleted` webhook, which needs the Clerk instance to reach the run's server. `tests/integration/account.test.ts` covers erasure through the webhook route.
